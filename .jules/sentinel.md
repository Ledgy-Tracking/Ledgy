## 2024-05-27 - [PouchDB Credential Leakage]
**Vulnerability:** Plaintext database credentials (username/password) were being embedded directly into the connection URL string when configuring PouchDB remote synchronization.
**Learning:** This is a common pattern that risks exposing sensitive credentials in application logs, error messages, and network proxy headers. PouchDB sync/replication methods do not support passing an `auth` object in their configuration options payload; the secure approach is to pass a completely separate, authenticated PouchDB instance to the `.sync()` or `.replicate.to()` methods.
**Prevention:** Never embed credentials in URL strings. Always instantiate dedicated service clients using secure authentication configuration objects and pass the authenticated instance to dependent functions.
